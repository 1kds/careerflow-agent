# CareerFlow

채용공고와 이력서를 비교하고 지원 준비 계획을 관리하는 툴콜링 기반 취업 준비 에이전트 MVP입니다.

## 역할 분담

- 모델: 사용자 의도 파악, 공고 역량 추출, 이력서 근거 비교, 준비 계획 제안
- 툴: 공고·이력서·분석 결과·할 일의 조회 및 저장, 날짜와 원문 근거 검증
- 사용자: 실제 할 일 등록 전 계획 승인

## 실행

### 웹 화면 (로컬 MVP)

```bash
source .venv/bin/activate
pip install -e '.[web,scraper]'
python -m careerflow.web --ask-key
```

터미널의 안내에 Gemini API 키를 붙여넣고 Enter를 누릅니다. 입력 내용은 화면에 표시되지 않으며 파일에 저장하지 않습니다. 이미 `GEMINI_API_KEY`를 설정했다면 `--ask-key`를 생략할 수 있습니다. 브라우저에서 http://127.0.0.1:8765 를 엽니다. `샘플로 먼저 체험하기` → 외부 전송 동의 → `내 경험과 공고 비교하기`로 가상 자료를 Gemini로 분석합니다. 샘플 버튼 자체는 API를 호출하지 않습니다.

- 이력서: 5MB 이하 PDF → 로컬 텍스트 추출 → 원문 검토·개인정보 제거. 스캔 PDF/OCR은 미지원이며 직접 입력 가능합니다.
- 공고: 본문을 붙여넣거나 원문 URL의 `공고 내용 가져오기`를 누를 수 있습니다. Scrapling이 공개 HTML 페이지의 JobPosting 구조화 데이터와 공통 본문 영역을 읽어 회사·직무·마감일·본문을 채웁니다. 원티드·사람인·잡코리아·점핏·인크루트·LinkedIn·Greenhouse·Lever 등의 공개 상세 페이지와 일반 기업 채용 페이지를 대상으로 하며, 사이트 구조에 따라 일부 항목은 직접 확인·수정해야 합니다. 수집은 로컬에서 실행되며 AI API를 호출하지 않습니다. 본문을 검토한 뒤 별도로 분석을 시작하세요. 로그인, CAPTCHA, 접근 제한 또는 JavaScript 렌더링이 필요한 페이지는 지원하지 않으므로 직접 붙여넣어 주세요. URL은 결과 다운로드와 보관함에 참고용으로 저장됩니다.
- 기본 모드: Gemini 실제 AI 분석입니다. 키가 없거나 API 호출에 실패하면 오류를 표시하며 키워드 비교로 자동 대체하지 않습니다. API 없이 체험하려면 분석 방식을 `로컬 키워드 비교`로 직접 선택하세요. 로컬 비교는 AI 분석이나 합격률 평가가 아닙니다.
- 실제 AI 분석: 서버 터미널에 기존 `GEMINI_API_KEY` 또는 `OPENAI_API_KEY`를 설정한 뒤 공급자를 선택하고 외부 전송에 동의합니다. 기존 툴콜링 에이전트를 재사용합니다. API 키는 브라우저에 입력하거나 전달하지 않습니다.
- 공고와 분석 결과는 `careerflow-web.db`에 자동 보관합니다. `--db presentation-web.db`로 웹 DB를 따로 지정할 수 있습니다. 같은 회사·직무·본문은 재분석 시 결과를 갱신하고, 본문이 다르면 별도 공고로 저장합니다. CLI의 기존 DB는 변경하지 않습니다.
- AI 분석 중에는 요청별 임시 SQLite를 사용하며 완료·오류 종료 후 제거됩니다. 원본 PDF와 이력서 원문은 영구 저장하지 않지만 **보관된 분석 결과에 개인정보가 포함될 수 있습니다.** 비정상 종료 시 임시 DB가 남을 수도 있으므로 개인정보를 제거해서 사용하세요. 브라우저 저장소는 사용하지 않습니다.
- `공고 보관함`에서 분석 결과와 공고 원문을 다시 볼 수 있습니다. 모델 비교 결과의 근거 부족·확인 필요 항목을 바탕으로 할 일 후보를 만듭니다. 각 후보에서 기한을 선택하고 `준비 할 일 등록하기`를 누르면 등록됩니다. 별도 동의 체크박스는 없으며 버튼 클릭을 등록 승인으로 처리합니다. 직접 작성도 가능합니다. 동일 공고·내용·기한은 중복 등록하지 않고, 공고 마감일 이후 기한은 거부합니다.
- 등록한 후보는 보관함을 다시 열어도 기존 기한과 `등록 완료` 상태로 표시됩니다. 같은 공고·내용의 할 일은 날짜가 달라도 중복 등록을 막습니다. 기존에 중복된 데이터는 자동 삭제하지 않습니다.
- `준비 할 일`에서 완료 체크와 해제가 가능합니다. 완료 체크와 별도인 삭제 선택 체크박스(전체 선택 지원)로 항목을 고르고 `선택 삭제`를 누릅니다. 삭제 확인 후 목록에서 숨기며 DB 기록은 보존합니다. 삭제한 할 일은 보관함에서 다시 등록할 수 있습니다. 보관함 조회, 할 일 등록·완료 체크·삭제는 AI API를 호출하지 않습니다. 실제 지원서 제출은 실행하지 않습니다. 이전 임시 분석 결과는 복구할 수 없으므로 다시 분석해야 보관됩니다.
- API 요청 결과는 실제 도구 이름·성공 여부만 표시하며 인자 원문은 로그에 남기지 않습니다. 결과 다운로드 파일에는 본인이 입력한 정보가 포함될 수 있습니다.
- 공고 스크래핑은 표준 HTTP 요청 한 번으로 공개 페이지를 읽습니다. 내부 네트워크 주소와 비표준 포트는 차단하고, HTTPS 인증서와 안전한 리디렉션 검사를 사용합니다. 사이트의 이용 조건과 접근 정책을 확인하고 공개된 공고 상세 페이지에만 사용하세요.
- **로컬 개발 전용입니다.** 인증·요청 속도 제한·운영용 PDF 격리가 없는 서버를 외부에 공개하지 마세요. AI 검증은 여러 호출이 발생할 수 있고 무료 공급자 티어에는 합성·비식별 데이터만 사용하세요.

### 기존 CLI

Python 3.11 이상과 사용할 공급자의 API 키가 필요합니다.

```bash
git clone https://github.com/1kds/careerflow-agent.git
cd careerflow-agent
python -m venv .venv
source .venv/bin/activate
pip install -e .
```

OpenAI로 실행:

```bash
export OPENAI_API_KEY="your-api-key"
careerflow --provider openai --trace
```

Gemini API로 실행:

```bash
export GEMINI_API_KEY="your-api-key"
careerflow --provider gemini --trace
```

공급자별 기본 모델은 OpenAI `gpt-5.6-terra`, Gemini `gemini-3.7-flash`입니다. 공급자는 `CAREERFLOW_PROVIDER`, 모델은 `OPENAI_MODEL`·`GEMINI_MODEL` 또는 공통 `--model` 옵션으로 변경할 수 있습니다.

CareerFlow는 Gemini Interactions API 호출에 `store=False`를 사용하고 대화 단계를 실행 중인 프로세스 메모리에서 관리합니다. 단, 입력 내용은 모델 처리를 위해 API 공급자에게 전송됩니다. Gemini 무료 티어에는 실제 이력서나 개인정보를 입력하지 말고 합성·비식별 데이터만 사용하세요. 실제 개인정보를 처리하려면 적법한 동의와 최소 수집 원칙을 적용하고, 유료 티어 약관 및 프로젝트의 데이터 설정을 먼저 검토해야 합니다.

## 데모 순서

1. `홍길동의 이력서를 등록해줘: ...`
2. `/paste`를 입력한 뒤 `ABC AI Engineer 공고를 저장하고 역량을 분석해줘:`와 공고 전체를 붙여넣고, 새 줄에 `/end`를 입력합니다.
3. `공고 1번과 이력서 1번을 비교해줘.`
4. `지원 마감일까지 할 일 계획을 보여줘.`
5. 계획을 확인한 뒤 `좋아, 등록해줘.`

`--trace`를 사용하면 모델이 선택한 툴과 실행 결과가 출력되어 발표 시 전체 흐름을 보여줄 수 있습니다. 이름, 이력서 원문, 이력서 근거, 채용공고 원문은 자동으로 마스킹되지만 자유 서술 필드에 개인정보가 포함될 수 있으므로 합성 데이터 데모에서만 사용하세요.

새 공고는 `save_job_posting_analysis` 툴 한 번으로 공고와 추출 역량을 함께 저장합니다. 따라서 정상적인 저장 요청은 **첫 모델 호출 → 툴 호출 1회 → 최종 모델 응답**의 API 2회로 완료됩니다. 같은 회사·직무·마감일과 같은 내용의 공고는 기존 ID를 재사용하고, 내용이 다르면 자동 덮어쓰기 대신 `update_job_posting`으로 수정하도록 안내합니다.

## 테스트

API 키 없이 저장·검증 툴을 테스트할 수 있습니다.

```bash
python -m unittest discover -v
```

## 핵심 안전장치

- 추출된 역량의 `evidence`가 공고 원문에 없으면 저장하지 않습니다.
- 동일 공고는 중복 저장하지 않고 기존 ID를 반환합니다.
- 공고를 수정하면 이전 역량과 매칭 결과를 무효화하고, 기존 할 일은 유지하면서 재검토 개수를 알려줍니다.
- `not_found`는 역량 부재가 아니라 이력서에서 근거를 찾지 못했다는 의미입니다.
- 지원 마감일 이후의 작업은 등록하지 않습니다.
- 시스템 프롬프트에서 사용자 승인 전 할 일 등록을 금지합니다.
